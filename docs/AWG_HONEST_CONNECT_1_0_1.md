# Честный статус AmneziaWG и правки UI (16 сентября 2026)

## Проблема

WireGuard/AmneziaWG не имеет фазы установления соединения: `setState(UP)`
только открывает TUN и запускает userspace-движок. Прежний `AwgManager`
сообщал `CONNECTED` сразу после этого, поэтому приложение показывало
«Защищено» даже когда сервер заблокирован или недоступен — интернет при этом
уходил в «чёрную дыру» до ручного отключения. GW-движок так не ведёт себя:
он даёт `CONNECTED` только после реального установления транспорта.

## Изменения

### Native (`AwgManager.kt`, `MainActivity.kt`)

- После `setState(UP)` менеджер остаётся в `CONNECTING` и опрашивает
  `GoBackend.getLastHandshake()` каждые 250 мс. `CONNECTED` уходит во Flutter
  только после первого успешного handshake — то есть когда сервер реально
  ответил на зашифрованное приветствие.
- Если handshake не пришёл за `HANDSHAKE_TIMEOUT_MS = 20 000` мс (четыре
  ретрансмиссии движка по 5 с, столько же ждёт GW), тоннель снимается,
  состояние — `ERROR`, а во Flutter возвращается
  `PlatformException(AWG_HANDSHAKE_TIMEOUT)`.
- Отмена (`disconnect`) во время ожидания handshake учитывается: тоннель
  снимается, состояние — `DISCONNECTED`, без ложного `CONNECTED`.
- В каждую секцию `[Peer]` без `PersistentKeepalive` добавляется
  `PersistentKeepalive = 25`. Так движок инициирует handshake сразу при
  поднятии (иначе он ждёт первого пользовательского пакета), а NAT-сессия
  не протухает в фоне. Серверное значение, если оно есть, не трогается.
- `isHandshakeAlive()` теперь опирается на handshake, а не на счётчики байт
  (исходящие байты растут и без ответа сервера).

### Flutter

- `VpnService` переводит `AWG_HANDSHAKE_TIMEOUT` в стабильный код
  `awg_handshake_timeout`; `error_messages.dart` локализует его как
  `errorServerUnreachable` на всех 14 языках.
- Введён счётчик поколений connect/cancel/disconnect: поздний результат
  отменённой попытки больше не перетирает актуальное состояние.
- Главный экран после неудачной попытки показывает локализованную причину
  (floating SnackBar), а не молча возвращается в «Не подключено».

### UI

- Welcome: «Я новый пользователь» / «Восстановить аккаунт» — та же геометрия,
  что у кнопки «Подключить»: плашка 58 px, текст по центру обеих осей.
  Раньше `minHeight` стоял снаружи `LiquidTile`, заливка сжималась по тексту,
  и подпись прилипала к верхнему краю.
- Список серверов: фишки «Все / AmneziaWG 3.1 / GW» прижаты к левому краю
  (`Wrap` растянут на всю ширину, `WrapAlignment.start`); кнопка обновления
  убрана — каталог и так перечитывается при каждом открытии листа.

## Без ложных срабатываний

- Порог 20 с намеренно с запасом: живой сервер отвечает за доли секунды,
  четыре ретрансмиссии покрывают медленный мобильный канал и DPI-задержки.
- Ждём именно handshake, а не трафик или DNS: handshake невозможен без
  реального ответа сервера и не зависит от приложений пользователя.
- Ожидание не блокирует отмену: второй тап по кнопке во время `CONNECTING`
  снимает тоннель немедленно.
- После `CONNECTED` поведение не меняется — постоянного «сторожа» нет, чтобы
  временная просадка сети не выкидывала работающее соединение.

## Проверка

- `flutter analyze --no-pub`: без замечаний. `flutter test --no-pub`: 74 теста,
  включая новые: маппинг timeout → `errorServerUnreachable` на 14 языках,
  «false без исключения» → `engine_not_ready`, отмена во время ожидания,
  центрирование welcome-кнопок, левое выравнивание фишек и отсутствие refresh.
- `AwgManager.kt` скомпилирован kotlinc 2.1 против stub-версии Android/AWG API
  и прогнан в JVM на трёх сценариях: handshake через 0,7 с → `CONNECTING,
  CONNECTED`; отмена во время ожидания → `DISCONNECTED`, `UP, DOWN`;
  без handshake → `ERROR` через 20,07 с, `UP, DOWN`. Инъекция keepalive
  проверена на конфиге без keepalive, с существующим значением и с двумя peer.
- Генерация локализаций, метаданные Play и `git diff --check` — без ошибок.

**Не проверено:** сборка APK/AAB, поведение на устройстве с настоящим
libwg-go и реальными заблокированными/живыми серверами. Перед релизом
прогнать connect/cancel/timeout на телефоне для обоих протоколов.
