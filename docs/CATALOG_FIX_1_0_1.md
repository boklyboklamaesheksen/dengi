# Пустой каталог серверов: исправление и проверка

## Причина

В предыдущем коммите значение подписи было вынесено из исходников в
`RABOCHIY_SIGNING_SECRET`. Это требовало специального параметра Flutter,
но обычная сборка из Android Studio продолжала успешно создаваться без него.
AWG выбрасывал исключение до HTTP-запроса, GW скрывал аналогичную ошибку,
а экран показывал пустой список. Это регрессия конфигурации, не установленный
побочный эффект обфускации.

Read-only проверка существующего `/vpn/api/v1/user/servers/load`:
без подписи — HTTP 403 / success=0; с подписью, соответствующей исходному
backend-контракту, — HTTP 200 / success=1, две записи. Аккаунты не создавались,
VPN-конфигурации пользователей не запрашивались, состояние backend не менялось.
Значение подписи и адреса серверов в отчёт и Git не включены.

## Что исправлено

- Gradle сам читает приватный `config/build-secrets.json` и передаёт значения
  как Dart defines. Работают также переменная окружения и явные Flutter defines.
  Явный параметр имеет приоритет. Без ключа APK/AAB не должен компилироваться;
  обычная синхронизация проекта допускается для первоначальной настройки.
- Отсутствующая конфигурация имеет отдельную ошибку на всех 14 языках.
  Список позволяет повторить запрос даже при отсутствии серверов.
- AWG и GW загружаются независимо и параллельно. Ошибка одного протокола
  больше не отменяет другой; повторные обновления объединяются.
- Ответ HTTP 200 с `success=0`, неверным `data` или полностью повреждёнными
  записями больше не считается успешным пустым каталогом.
- Успешный пустой каталог очищает старые строки. Ошибочный ответ не затирает
  хороший кеш; кеш изолирован по аккаунту и backend. Ответ после logout не
  возвращает прошлый аккаунт в UI и не сохраняет его конфигурацию заново.
- Уже созданный API-клиент использует обновлённый домен Remote Config.
  Загруженные ранее remote-настройки применяются до сетевого обновления;
  небезопасные/некорректные URL отклоняются, явный локальный override сохраняется.
- Фоновая загрузка каталога больше не создаёт аккаунт без выбора пользователя
  на экране приветствия. Создание через onboarding сохранено.
- Удалённый сервер не остаётся выбранным со старой конфигурацией; автовыбор
  предпочитает бесплатные доступные узлы для пользователей без Premium.
- `ServerConfig.copyWith` сохраняет GW-конфигурацию. Дешифрование GW принимает
  стандартный SEC1 uncompressed ключ с префиксом `04`, а не только сжатый/raw
  и прежний нестандартный формат; нечётная длина hex отклоняется.
- При сбросе только RX или TX статистика не прибавляет заново другой счётчик;
  окно статистики включает пересекающий его начало часовой bucket.
  Точность окна остаётся часовой, а не посекундной.
- Экран приветствия прокручивается на коротком экране, кнопки растут под
  длинный текст; русское название больше не заменяется английским wordmark.
  Ошибка каталога находится внутри прокручиваемого списка. Фильтры переносятся,
  заголовок не выталкивает кнопки, область закрытия увеличена до 48×48.
- Исправлены все 13 исходных замечаний Flutter analyzer, включая использование
  BuildContext после await в disclosure split tunneling. Исключения линтера
  и отключение проверок для этого не добавлялись.

## Версия и окружение

Версия остаётся **1.0.1 (3)**. В отчёте Play уже фигурировал `1.0.0 (2)`;
повторное использование versionCode=2 не годится для обновления в Play.
Gradle перечитывает pubspec при каждом sync, обновляя Flutter extension,
из которого Android получает versionName/versionCode. Поэтому даже старые
`flutter.versionName=1.0.0` и `flutter.versionCode=2` в local.properties
не переопределяют версию. Settings читает `PackageInfo`, а не константу.

Проверено на Flutter **3.47.4 stable** / Dart **3.13.3**, JDK 17, Gradle 8.14.
Версия SDK зафиксирована в `.flutter-version`, минимумы — в pubspec,
разрешённые зависимости — в `pubspec.lock`. Старые экспериментальные и
внутренние Gradle-флаги удалены. AGP 8.13.2 и Kotlin 2.2.20 сохранены;
миграция на AGP 9 без Android-сборки не выдаётся за проверенное обновление.

## Проверка

- `flutter analyze --no-pub`: **No issues found**.
- `flutter test --no-pub`: **68 тестов проходят**, включая регрессии подписи, HTTP, кеша,
  Remote Config, AWG/GW, logout, статистики, viewport и локализаций.
- UI: welcome и пустой каталог на 320×480 со шрифтом ×1.5 на 14 языках;
  частичная ошибка + доступный GW; refresh → ошибка конфигурации → успешный retry.
- `tools/test_android_build_config.py`: шесть сценариев на настоящем Gradle,
  включая блокировку компиляционной задачи без ключа, приоритет файла/CLI/env
  и независимость версии от старого local.properties. Это stub-проект,
  **не синхронизация полного Android-проекта в Android Studio**.
- Генерация переводов, метаданные Play, номера версии, `git diff --check`.

Все HTTP-тесты воспроизводимы с фиктивными ключами и тестовыми ответами,
без доступа к production. UI проверялся в Flutter test runner, не на телефоне.

## Перед следующей сборкой на компьютере разработчика

1. Выбрать Flutter 3.47.4 в Android Studio и выполнить `flutter pub get`.
2. Скопировать example JSON в `config/build-secrets.json`, указать действующее
   согласованное с backend значение. Git его игнорирует. Одна только копия
   примера с пустой строкой не является настроенной конфигурацией.
3. Собрать release с приватным keystore и проверить на телефоне оба протокола,
   VPN permission, connect/cancel/disconnect, аккаунт и split tunneling.
4. Сохранить R8 mapping/Dart symbols/native symbols и получить symbolicated
   stack для прежнего SIGSEGV. Без APK/AAB и устройства нельзя честно
   утверждать, что исправлены все native-крэши и предупреждения Android lint.

Исходный общий ключ уже был публичен: требуется координированная ротация,
а не повторная публикация в новом репозитории. Dart define не делает секрет
неизвлекаемым из приложения. Серверную аутентификацию он не заменяет.
